# 注意事项

## 提交问题

在对应项目的 Issues 页面反馈问题时，请尽可能附上以下信息，方便维护人员定位：

- 运行环境：操作系统、软件版本和使用的项目分支。
- 报错日志：说明执行的命令，附上完整报错或相关截图。
- 复现步骤：按顺序写出操作过程，并说明预期结果与实际结果。

## Pull Request

- 提交 Pull Request 时，标题需要总结这次修改的内容或者为什么修改；

- 提交 Pull Request 时若提示冲突，先确认 PR 的目标分支和自己的工作分支，再将上游更新合并到工作分支并解决冲突。`Sync fork` 只更新个人仓库的默认分支，不会自动修复 PR 所在的工作分支；解决后还要把工作分支推送到个人仓库。


## 代码审核

- 审核按每一行代码对 Pull Request 进行评论时，注意在 `Files changed` 页面点右上角绿色的 `Submit review`（旧版叫 `Review changes`），选择 `Comment` 后，再点一次弹窗里的 `Submit review`，否则评论只留在本地，其他人看不到。
